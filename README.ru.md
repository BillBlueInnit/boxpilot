# BoxPilot

[English](README.md) · [简体中文](README.zh-CN.md) · **Русский** · [Как пользоваться](docs/usage.ru.md)

Аккуратный настольный прокси-клиент для Windows, macOS и Linux, написанный на Rust с
[GPUI](https://gpui.rs) (через gpui-kit). Он управляет ядром [sing-box](https://sing-box.sagernet.org)
и содержит встроенный конвертер подписок.

## Быстрый старт

Скачайте BoxPilot для своей платформы на странице
[Releases](https://github.com/BillBlueInnit/boxpilot/releases):

- **Windows**: `BoxPilot-<версия>-windows-x64.zip` — распакуйте и запустите `boxpilot.exe`.
- **macOS**: `BoxPilot-<версия>-macos-arm64.dmg` (Apple silicon) или `-macos-x64.dmg` (Intel) — откройте
  образ и перетащите BoxPilot в «Программы». Приложение не нотаризовано: при первом запуске щёлкните
  по нему правой кнопкой и выберите **Открыть** (или разрешите запуск в «Системные настройки →
  Конфиденциальность и безопасность»).
- **Linux**: `BoxPilot-<версия>-linux-x64.tar.gz` — распакуйте и запустите `boxpilot`.

Или соберите сами:

```
cargo run --release -p boxpilot
```

Затем:

1. **Настройки → Ядро sing-box → Скачать последнюю версию.** Ядро не входит в комплект: BoxPilot
   загружает официальный выпуск для вашей платформы с GitHub (через прокси, если он запущен, или через
   заданный префикс зеркала).
2. **Подписки → Добавить** и вставьте ссылку от провайдера (или **Вставить**, чтобы импортировать из
   буфера обмена).
3. **Обзор → Подключить.**

Подробная пошаговая инструкция — в [docs/usage.ru.md](docs/usage.ru.md). Где хранятся данные, указано
в таблице [Платформы](#платформы); в Windows папка `data` рядом с `boxpilot.exe` включает переносной режим.

## Возможности

- **Конвертер подписок**: ссылки v2ray / Shadowrocket (обычные или base64), YAML Clash / Clash.Meta и
  JSON sing-box. Поддерживаются VLESS (REALITY, Vision), VMess, Trojan, Shadowsocks (включая 2022, obfs и
  v2ray-plugin), Hysteria 2 (смена портов), Hysteria, TUIC, AnyTLS, WireGuard, SOCKS, HTTP(S) и SSH поверх
  транспортов ws / grpc / h2 / httpupgrade / quic. Неподдерживаемые записи (SSR, xhttp…) попадают в журнал
  и не прерывают импорт.
- **Обновление подписок**: свой интервал для каждой подписки, обновление при запуске, догоняющее
  обновление после простоя, быстрый повтор после ошибок, переход с прокси на прямое соединение, свой
  User-Agent, фильтры включения / исключения по регулярным выражениям (применяются без загрузки),
  трафик и срок действия из `subscription-userinfo`, название и интервал от провайдера. После пакета
  обновлений ядро перезагружается один раз.
- **Прокси**: режимы «Правила» / «Глобальный» / «Напрямую» (переключаются на лету), группы выбора и
  «Авто» для каждой подписки, проверка задержки, системный прокси (восстанавливается при выходе и после
  сбоев), режим TUN с перезапуском от имени администратора, доступ из локальной сети, UDP через прокси
  (или напрямую) и необязательная блокировка QUIC. Изменения настроек объединяются в одну перезагрузку
  ядра, автопереключение не обрывает открытые соединения, упавшее ядро перезапускается автоматически.
- **Локальные узлы и обмен ссылками**: отдельные узлы добавляются по ссылкам (ss, vmess, vless, trojan,
  hysteria2, tuic, anytls, socks5, http(s), wireguard, ssh — или списки узлов Clash / sing-box) в группу
  **Локальные узлы**; любой узел — из подписки или локальный — можно скопировать обратно как ссылку.
- **Группа «Авто»**: быстрый отклик, стабильность (переключение только при сбое или большой разнице),
  порядок списка (переход вниз по списку при сбое и обратно) или максимальная скорость (периодические
  замеры скорости самых быстрых узлов) — с возможным ограничением одним регионом.
- **Замер скорости**: скорость загрузки и реальная задержка (новый HTTPS-запрос через узел) для одного
  узла или всех показанных — через отдельный локальный зонд, ваш выбор узла не меняется.
- **Правила**: импорт наборов правил по ссылке или из файла — sing-box `.srs` / `.json`, провайдеры
  правил Clash (YAML `payload:`, domain / ipcidr / classical) и файлы ACL4SSR `.list`, которые
  преобразуются в наборы sing-box. Каждый набор направляет трафик в прокси, напрямую, в блокировку или
  в любую группу — в заданном вами порядке — и обновляется по своему интервалу. **Импорт ACL4SSR**
  читает `.ini` subconverter (например, ACL4SSR_Online_Full) и создаёт наборы для всех строк `ruleset=`
  с нужным действием; после импорта они выключены, вы включаете нужные (есть «Включить все» /
  «Отключить все»). Набор правил может получить **свою группу узлов** на странице прокси — узел
  выбирается вручную или автоматически теми же способами и с тем же фильтром региона, что и «Авто»;
  файл набора можно открыть в текстовом редакторе — сохранённые изменения применяются сами. Есть
  встроенный обход Китая и блокировка рекламы, а также свои правила (`ТИП,ЗНАЧЕНИЕ,ЦЕЛЬ`).
- **DNS**: DoH / DoT / DoQ / UDP, FakeIP, IPv6. Наборы правил кэшируются приложением и передаются
  sing-box как локальные файлы, поэтому заблокированный GitHub или нерабочий узел не мешают запуску ядра.
- **Приложение**: English, 简体中文, 繁體中文 и Русский (следует языку системы, переключается на лету);
  запуск от имени администратора (автозапуск через задачу планировщика с наивысшими правами — без
  запроса UAC); значок в трее с переключателями режима, системного прокси и TUN; сворачивание в трей,
  один экземпляр, автозапуск (можно свёрнутым), график трафика, список соединений, журнал, светлая и
  тёмная темы, цвет темы и полупрозрачное окно (Mica, Mica Alt или Acrylic в Windows 11, системное
  размытие в macOS и KDE Plasma).
- **Страница прокси**: код страны у каждого узла — из названия (флаг, город, код), иначе по GeoIP
  сервера, иначе (anycast / CDN или частные адреса) по выходному IP, проверенному через сам узел.
  Облегчённый режим выгружает интерфейс, пока приложение работает в трее.
- **Обновления приложения**: проверка GitHub Releases раз в день; устанавливать автоматически, только
  напоминать или не уведомлять (Настройки → Обновления). Обновление заменяет исполняемый файл на месте и
  вступает в силу после перезапуска.
- **Анимация**: каждый переход — затухающая пружина (аналитический решатель GPUI): движение плавно
  замедляется и останавливается как у физического предмета, сохраняет скорость при прерывании и учитывает
  параметр «Уменьшить движение».

## Платформы

BoxPilot работает на всех платформах, которые поддерживает GPUI, — Windows 10/11, macOS (Apple silicon и
Intel) и Linux (X11 и Wayland) — с одинаковыми возможностями. Там, где системы различаются, используется
родной механизм каждой:

| | Windows | macOS | Linux |
| --- | --- | --- | --- |
| Установка | zip | `.dmg` с BoxPilot.app (Dock, Launchpad) | tar.gz |
| Окно | без рамки, родная рамка, макеты прикрепления на кнопке «Развернуть», Mica по желанию | родные кнопки-«светофор» | клиентские декорации (или оконного менеджера) |
| Кнопки заголовка | значки Segoe Fluent / MDL2, цвета WinUI | «светофор» AppKit | стиль Adwaita (GNOME) или Breeze (KDE), порядок и сторона из `button-layout` |
| Системный прокси | WinINet (реестр) | `networksetup` для каждой сетевой службы | KDE `kioslaverc` и GNOME `gsettings` (оба — для KDE, GTK и Firefox) |
| Права для TUN | запуск BoxPilot от имени администратора (автозапуск через планировщик, без UAC) | ядро получает setuid root после одного запроса пароля; пока TUN работает, DNS указывает на него | `CAP_NET_ADMIN` для ядра через `pkexec setcap` или setuid-ядро, если `setcap` не установлен |
| Автозапуск | ключ Run / задача планировщика | LaunchAgent | XDG autostart |
| Закрытие в трей | скрывает окно | скрывает приложение (значок в Dock возвращает его) | закрывает окно (трей открывает снова) |
| Очистка ядра при сбое приложения | объект задания | очистка зависших процессов при следующем запуске | сигнал о смерти родителя + очистка зависших процессов |
| Папка данных | `%APPDATA%\BoxPilot` | `~/Library/Application Support/BoxPilot` | `$XDG_CONFIG_HOME/BoxPilot` |

Для значка в трее на Linux нужен трей с поддержкой AppIndicator (в GNOME — расширение AppIndicator).

`.github/workflows/ci.yml` собирает и тестирует проект на Windows, macOS (arm64 и x64) и Linux:
модульные тесты, проверка каждого сгенерированного конфига через `sing-box check`, живой тест движка с
настоящим ядром (запуск, группы, выбор, задержка, смена режима, трафик, перезагрузка, остановка) и
проверка запуска интерфейса (`boxpilot --smoke-test`).

`.github/workflows/release.yml` публикует выпуск при отправке тега версии. Тег должен совпадать с
версией рабочего пространства в `Cargo.toml`:

```
git tag v1.0.0
git push origin v1.0.0
```

К выпуску прикладываются `BoxPilot-<версия>-<платформа>.zip|tar.gz` для Windows x64, macOS arm64/x64 и
Linux x64 — эти имена ищет встроенное обновление, — а также `.dmg` для каждой сборки macOS.

## Структура

| Путь | Назначение |
| --- | --- |
| `crates/core` | Без интерфейса. Конвертер (`convert/`), генератор конфигурации (`config.rs`), движок с жизненным циклом процесса, планировщиком и обновлениями (`engine.rs`), клиент Clash API, загрузчик ядра и интеграция с системой (`sys.rs`). |
| `crates/core` (`rules.rs`) | Преобразование наборов правил (Clash / ACL4SSR → sing-box) и разбор `.ini` ACL4SSR. |
| `crates/app` | Интерфейс на GPUI: страницы в `src/ui/`, пружины в `ui/anim.rs`, переводы в `i18n.rs`, трей, единственный экземпляр, работа с окном. |

`cargo test -p boxpilot-core` запускает тесты конвертера и конфигурации. Проверить сгенерированные
конфиги настоящим ядром:

```
cargo run -p boxpilot-core --example gen_config -- out
sing-box check -c out/everything-1.14.json
```

Конфиги рассчитаны на sing-box 1.12+ (рекомендуется 1.14): действия правил, конечные точки WireGuard,
новый формат DNS-серверов и `http_clients`.
